# Neon Rift Survivor V4.2 — Rift Arsenal Update

## Purpose
V4.2 is the replayability/content follow-up to V4.1. The focus is build variety, optional challenge systems, stronger mid-run decisions, and better long-term reasons to replay without turning the project into a full V5 rewrite.

## Core release goals

### 1. New original weapons
Add 3–5 weapons with clearly different play patterns:
- Rift Beam — sustained directional damage with heat/charge behavior.
- Chain Blade — rotating/chained melee arcs with strong crowd control.
- Drone Swarm — autonomous orbiting drones with support/damage specialization.
- Gravity Well — periodic pull/control zone followed by burst damage.
- Burst Cannon — slower high-impact volleys with strong crit scaling.

All visuals, audio, names, code, and tuning should remain original to Neon Rift Survivor.

### 2. Branching EVO paths
At least two V4.2 weapons should support two EVO routes.

Examples:
- Rift Beam + Fuel → Solar Lance: larger sustained damage route.
- Rift Beam + Cooldown → Phase Array: faster pulse / split-beam route.
- Drone Swarm + Armor → Guardian Matrix: defense/shield retaliation route.
- Drone Swarm + Crit → Hunter Protocol: aggressive multi-target route.

Known recipes should be visible in the Build Codex after discovery. Undiscovered routes can remain partially hidden.

### 3. New Ultimate Synergies
Add synergy recipes that use the V4.2 weapon set. Synergies should not activate twice and should clearly communicate activation with UI, VFX, and SFX.

### 4. Mini-bosses
Add special mid-run encounters before main bosses. Mini-bosses should:
- have a distinct name/health presentation,
- use one or two unique attack patterns,
- scale with mode/difficulty,
- drop an upgraded cache,
- never overlap unfairly with another boss unless a mode explicitly allows it.

### 5. Rift Contracts
Optional pre-run objectives that award Rift Cores, badges, or progression/cosmetic rewards.

Example contracts:
- Survive 5 minutes without healing.
- Defeat 2 bosses with no shield remaining.
- Reach 3 EVOs in one run.
- Clear an Expedition with only 3 weapons.
- Defeat a mini-boss before 4:00.
- Finish a run with a selected Arena Modifier active.

Contracts must clearly show success conditions before the run and must never silently change mid-run.

### 6. Arena Modifiers
Optional modifiers that alter runs and apply transparent score/reward multipliers.

Examples:
- Low Gravity — faster movement / altered knockback.
- Elite Surge — more elites, higher score multiplier.
- Fragile Core — lower max HP, higher Rift Core rewards.
- Mythic Flux — harder enemies with slightly better high-rarity promotion chance.
- Boss Rush — earlier/faster boss schedule.
- No Recovery — reduced/disabled passive healing.

The selected modifier, exact effect, and reward multiplier must be visible before the player presses Start.

### 7. Expanded boss rewards
Increase cache variety so boss rewards are less repetitive. Include damage, defense, shield, movement, cooldown, area, rarity, reroll, and build-specific rewards.

## Replayability systems

### Weapon Mastery
Track persistent XP/mastery per weapon. Rewards should be non-pay-to-win and can include:
- mastery badges,
- cosmetic VFX variants,
- profile/codex milestones,
- challenge unlocks,
- small capped utility bonuses only if balance remains healthy.

### Elite Affixes 2.0
Add new affixes such as:
- Reflective,
- Teleporter,
- Summoner,
- Frenzied,
- Cryo.

Each affix needs readable visuals and should not create unavoidable damage.

### Run Mutators
Allow players to intentionally increase difficulty for a higher score/reward multiplier. Mutators should stack only when clearly supported and displayed.

### Boss Variants
Reuse existing boss identities with alternate phase patterns/attacks instead of creating a completely separate boss engine for every variant.

### Ascension milestones
Reward high Ascension progress with badges, profile cosmetics, challenge tiers, or codex completion markers.

### Daily Challenge expansion
Daily seeds may force or bias:
- Operator,
- weapon,
- arena,
- modifier,
- boss condition,
- rarity rule.

Daily results must store the exact challenge config version.

## Collection / profile systems

### Build Codex
Track discovered:
- weapons,
- EVO recipes,
- Ultimate Synergies,
- Operators,
- classes,
- bosses,
- contracts,
- achievements.

### Favorite Builds
Allow players to save a few build summaries from completed runs.

### Personal-best ghost data
Optional lightweight prior-run benchmark data such as prior score pace, boss timing, or movement trace. This is not real-time multiplayer.

### Leaderboard filters
Where supported, filter by:
- mode,
- arena,
- Operator,
- class,
- difficulty,
- Daily Challenge.

Keep lifetime records even if seasonal boards are added.

### Shareable results
Upgrade the run-share format with score, rank, Operator, class, arena, weapons, EVOs, modifiers, and personal-best status.

## Accessibility
- Colorblind-safe danger markers.
- Scalable HUD and larger text mode.
- High-contrast boss telegraphs.
- Reduced-motion compatible VFX for new weapons and bosses.
- Do not rely on color alone for elite affixes or danger zones.

## Performance
- Expand object pooling for enemies, projectiles, drops, drones, and VFX.
- Add adaptive VFX density.
- Maintain a low-end mobile preset.
- Cap expensive particles and projectile trails under heavy load.
- Keep V4.1 performance overlay compatible with V4.2 entities.

## Data / save compatibility
V4.2 should migrate from V4.1 without losing:
- local/global leaderboard references,
- run history,
- Rift Cores/progression,
- achievements,
- settings,
- personal records.

New persistent data should include:
- weaponMastery,
- codex discoveries,
- completed contracts,
- contract streak/state if used,
- favorite build summaries,
- seasonal metadata if introduced.

Every save migration must be versioned and reversible via export backup.

## Suggested architecture
Keep V4.2 modular rather than expanding one giant file. Suggested files:
- `src/v4.2/weapons.js`
- `src/v4.2/evolutions.js`
- `src/v4.2/minibosses.js`
- `src/v4.2/contracts.js`
- `src/v4.2/modifiers.js`
- `src/v4.2/mastery-codex.js`
- `src/v4.2/ui.js`
- `v4.2.css`

Use compatibility hooks around the existing V4/V4.1 systems where possible.

## Testing gate
Before V4.2 stable:
- Every new weapon tested from Lv1 to max to EVO.
- Every branching EVO route tested independently.
- New Ultimate Synergy activation and duplicate prevention tested.
- Mini-boss spawn, reward, death, despawn, and overlap behavior tested in every mode.
- Contract success/failure/reward persistence tested.
- Arena Modifier effects and score multipliers validated.
- Weapon Mastery save/migration tested.
- Codex discovery/unlock persistence tested.
- V4.1 results/leaderboard compatibility preserved.
- Mobile and controller regression pass.
- Heavy-wave performance test with all V4.2 weapon/VFX combinations.
- V4.1 save → V4.2 migration tested with no loss of progression/history.
- Offline/PWA regression pass.

## Scope boundary
V4.2 is not the place for co-op, real-time multiplayer, a mandatory account system, or a major world/progression rewrite. Those belong in a future V5 scope.
