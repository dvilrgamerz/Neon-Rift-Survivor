# Neon Rift Survivor V4.1 — Community Test Update

V4.1 is a focused polish, feedback, telemetry, results, controls, accessibility, and leaderboard release built on top of V4 Rift Expedition.

## Product goal

V4 already has enough content to support meaningful playtesting. V4.1 should make it easier to learn from players, improve readability, tighten balance, and introduce optional online competition without breaking offline play.

## Priority roadmap

### P0 — ship before V4.1 stable

- In-game **Feedback** and **Report Bug** buttons.
- Auto-filled diagnostics for bug reports: build/version, mode, arena, Operator, class, difficulty, elapsed time, score, bosses, browser/device basics, performance snapshot, and recent error/event summary.
- **Results Screen V2** with richer run stats.
- **Personal Records** and clear `NEW BEST` feedback.
- **Share Run** copy action for Reddit/X/Discord.
- **Boss telegraph/readability pass**.
- **VFX/SFX 2.0** for EVO, shield break, dodge, critical hits, boss phase changes, Mythic picks, achievements, new records, and low HP.
- **Mobile/control polish** for touch targets, joystick safe zones, landscape HUD, auto-aim tuning, and readability.
- **Balance pass** based on playtest data.
- **Global Leaderboard Beta** with local/offline leaderboard fallback.

### P1 — follow-up

- Seeded Daily Challenge modifiers.
- Achievement unlock toast + new achievements.
- Controller prompts, menu navigation, disconnect/reconnect handling.
- Save schema/build display, export timestamp, migration/import warnings.
- Optional performance overlay: FPS, enemy count, projectile count, VFX count, quality mode.
- In-game `What's New in V4.1` panel.

## Global Leaderboard Beta

The existing local leaderboard must remain available offline.

Recommended optional backend: Supabase.

### Submission flow

1. Client requests a one-use `run_id` before a scored run.
2. Server records start timestamp, build, config, and seed.
3. Client plays normally.
4. Client submits a summary to a validation function.
5. Server validates the run.
6. Status becomes `accepted`, `quarantined`, or `rejected`.
7. Only accepted scores appear on the public board.

### Validation checks

- one-use run ID
- server-observed start/finish timing
- supported build/config version
- valid mode/arena/Operator/class/difficulty enums
- score and boss-count ceilings consistent with elapsed time
- plausible upgrade/EVO/Mythic counts
- duplicate submission protection
- submission rate limiting
- reject NaN/negative/overflow/impossible values

Do not put a secret signing key in browser JavaScript and do not allow anonymous direct inserts into the final leaderboard table.

## Scope rule

V4.1 is not another major content expansion. Avoid adding more arenas/operators/weapons unless playtest data shows a clear need. Focus on feedback conversion, readability, balance, controls, telemetry, results, stability, and safer competition.
